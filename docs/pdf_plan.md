# План PDF (2 страницы)

## Страница 1. Проблема → данные → выводы → решение

### 1. Проблема
Бизнес видит покупки, но не видит путь к ним. Нет cost, нет касаний, нет связи «реклама → покупка».

### 2. Данные
- Продажи: 795 строк, 606 покупателей, 18 курсов, 04.08–10.09.2026.
- Рекламная активность: размещения, репосты, подписчики (TGStat).
- Три всплеска продаж: 8–10.08, 22–24.08, 4–6.09.

### 3. Выводы
- Пики подписчиков ≠ пики продаж. Корреляция ≈ 0.
- Всплески совпадают с внутренними событиями (скидки, запуски).
- Вклад внешней рекламы отдельно посчитать нельзя.
- Исторический ROMI по размещениям восстановить невозможно.

### 4. Решение
MVP системы измерения: реестр размещений → tracking source → атрибуция → ROMI.
Сегодня — demo на синтетике. Завтра — реальный ROMI.

## Страница 2. Архитектура → ROMI → MVP → план внедрения

### 1. Архитектура

Реклама → placement_id → пользователь → покупка → выручка → атрибуция → ROMI → решение по бюджету

### 2. Атрибуция
- Last touch (основная), linear (сравнение).
- Окно: 14 дней.
- Органика — отдельно.

### 3. ROMI

ROMI = (Attributed Revenue − Cost) / Cost

- ROMI_attr — считаем.
- ROMI_inc — не считаем (нет данных).

### 4. MVP
- `src/placements.csv` — реестр размещений.
- `src/romi.py` — калькулятор.
- `outputs/romi_demo.csv` — результат.
- `docs/architecture.md`, `docs/spec.md`, `docs/tracking.md` — описание.

### 5. План внедрения
1. Запустить tracking-ссылки на каждое размещение.
2. Логировать cost в реестр.
3. Через 1–2 месяца — первый честный ROMI.
4. Провести A/B для проверки инкрементальности.
5. Перераспределить бюджет по ROMI.

### 6. Ответ на вопрос «300 000 ₽»
Не выбирать канал по прошлой выручке. Сначала собрать данные → оценить ROMI → сравнить → перераспределить.
